# TYB: ежедневник, список покупок, банк времени

Спецификация для реализации (дата: 2026-10-27). Проект: Kotlin + Compose, Room, DataStore, minSdk 36.

---

## 1. Правила для приложений (общая модель)

Сначала нужна единая модель правил, иначе банк не к чему привязать.

У каждого контролируемого приложения (или группы приложений) есть:

- **`permanentBlock: Boolean`** — галочка «заблокировать навсегда». Если включена, все остальные правила игнорируются, приложение закрыто всегда.
- **Расписание по типам дней**: `WEEKDAY` (пн–пт) и `WEEKEND` (сб–вс). Позже можно расширить до каждого дня недели отдельно.

Для каждого типа дня одно из правил (можно комбинировать лимит и окна):

| Режим | Смысл |
|---|---|
| `NONE` | без ограничений |
| `LIMIT(minutes)` | не больше N минут в день |
| `ALLOW_WINDOWS([start–end])` | можно только в этих интервалах, остальное время закрыто |
| `DENY_WINDOWS([start–end])` | закрыто в этих интервалах, остальное время можно |
| `LIMIT + ALLOW_WINDOWS` | N минут, но только внутри окна |

Важно: «разрешено в 7 вечера» в UI задаётся как **интервал** (19:00–20:00), а не точка времени.

## 2. Банк времени

### 2.1 Начисление
- Начисляется **только с дней, где правило `LIMIT`** (будни). Окна и вечная блокировка ничего не дают.
- Сумма: `unused = max(0, limit - used)`, начисляется в 00:00 за прошедший день.
- **Лимит берётся снимком на начало дня.** Если днём поднять лимит с 30 до 120 минут, в банк всё равно уйдёт по старым 30. Защита от «накрутки».
- Если правило в этот день отключали (пауза, удаление), за день ничего не начисляется.
- **Потолок банка**: например 180 минут (настраиваемо). Сверх потолка не копится.
- **Сгорание**: банк обнуляется в понедельник 00:00 (недельный цикл «копишь в будни, тратишь в выходные»). Альтернатива на выбор пользователя: не сгорает, но действует потолок.

### 2.2 Банк общий или по приложениям
Рекомендация: **один общий банк минут**. Копится с любых приложений с лимитом, тратится на любое приложение, где траты разрешены. Проще в UI и понятнее («у меня 85 минут»). Раздельные банки можно добавить позже.

### 2.3 Трата
- Тратить можно **только в выходные** (настраиваемо: «тратить можно в: сб, вс»).
- Трата **осознанная, а не автоматическая**: когда время кончилось, на экране блокировки кнопка «Взять из банка» с выбором 10 / 15 / 30 минут. Минуты списываются сразу, открывается «сессия» на это время. Неиспользованный остаток сессии возвращается в банк.
- Банк не уходит в минус.

### 2.4 Как банк работает с разными правилами в выходные

| Правило в выходной | Что делает банк | Цена |
|---|---|---|
| `LIMIT(N)` | добавляет минуты сверх N | 1 мин банка = 1 мин |
| `ALLOW_WINDOWS` (можно только 19–20) | позволяет зайти **вне окна** | 1 мин = **2 мин** банка |
| `DENY_WINDOWS` (нельзя 19–20) | по умолчанию **не работает**, запретное окно жёсткое | опция «можно выкупать» с ценой ×3 |
| `permanentBlock` | **не работает никогда** | — |

Логика: окно «запрещено» обычно ставят ради чего-то важного (уроки, ужин, сон), поэтому по умолчанию банк его не пробивает. Окно «разрешено только» мягче, поэтому выход за него можно купить, но дороже. Множители хранятся в настройках.

### 2.5 Вечная блокировка
- Банк не работает, и это приложение не начисляет в банк.
- **Снятие галочки с задержкой**: после нажатия «снять» приложение откроется только через 10 минут (таймер видно, можно отменить). Это защищает от импульса «на минутку», ради которого вообще делается приложение. Длительность задержки настраивается.

### 2.6 История
Таблица транзакций банка, чтобы было видно, откуда минуты и куда ушли (и для отладки):
`bank_tx(id, timestamp, amount (+/-), reason: EARN_DAILY | SPEND | REFUND | EXPIRE | REWARD_TASK, appPackage?, note?)`.
Баланс = сумма транзакций (или кэш в DataStore, пересчитываемый из таблицы).

## 3. Ежедневник с напоминаниями

### 3.1 Задача
`task(id, title, note?, dueAt?, done, doneAt?, createdAt, rewardMinutes?, reminderRule?)`

### 3.2 Правило напоминания (sealed class, хранить JSON в Room)
- `Once(at: DateTime)` — один раз в дату и время.
- `After(duration)` — «напомни через 2 часа»: при сохранении превращается в `Once(now + duration)`.
- `Interval(every: Duration, from: DateTime, anchor: FROM_START | FROM_DONE)` — «каждые 7 часов». `FROM_START` — по сетке от исходного времени, `FROM_DONE` — от момента, когда отметил выполненным.
- `Weekly(days: Set<DayOfWeek>, time)` — «каждую субботу в 21:00», «пн/ср/пт в 8:00».
- `Monthly(dayOfMonth, time)` — «каждое 1-е число».
- Опционально `until: DateTime?` / `count: Int?` — когда прекратить повторы.

У каждой задачи хранится вычисленное `nextFireAt`. После срабатывания считается следующее и ставится новый будильник.

### 3.3 Уведомление
- Кнопки: **Готово**, **Отложить** (+10 мин, +1 ч, завтра в это же время).
- «Тихие часы» (например 23:00–07:00): напоминание, выпавшее на них, переносится на конец тихих часов.

### 3.4 Техника (Android 16)
- `AlarmManager.setExactAndAllowWhileIdle` + `BroadcastReceiver`, который показывает уведомление и планирует следующий раз.
- Разрешения: `POST_NOTIFICATIONS`, `USE_EXACT_ALARM` (подходит приложениям-напоминалкам; для Google Play может понадобиться обоснование) или `SCHEDULE_EXACT_ALARM` с запросом у пользователя.
- Перепланировать все будильники при `BOOT_COMPLETED`, `TIME_SET`, `TIMEZONE_CHANGED`, после обновления приложения (`MY_PACKAGE_REPLACED`).
- WorkManager для точных напоминаний не подходит (неточный), только для фоновых дел вроде начисления банка в полночь.

## 4. Список покупок

- Несколько списков («Продукты», «Хозтовары»).
- `shopping_item(id, listId, text, quantity?, checked, position, checkedAt?)`.
- Быстрый ввод: Enter добавляет пункт и оставляет фокус в поле.
- Тап по пункту: зачеркнуть (checked), такие уезжают вниз списка.
- Свайп: удалить (со Snackbar «Отменить»).
- Кнопка «Убрать купленные».
- Автоподсказки из ранее введённых пунктов.
- «Поделиться списком» как текст (через стандартный share).

## 5. Связки, которые делают приложение цельным (идеи)

1. **Экран блокировки показывает задачи.** Вместо «нельзя» — «Вместо этого: 3 задачи на сегодня» с кнопкой в ежедневник. Самая сильная связка «верни себе мозг».
2. **Задачи дают минуты в банк.** У задачи поле `rewardMinutes` (например +10). С потолком в день (например 30 мин), иначе всё превратится в фарм.
3. **Режим фокуса для задачи.** «Делаю уроки 45 минут»: на это время блокируются все отвлекающие приложения, по окончании уведомление.
4. **Пауза перед открытием.** Перед запуском приложения с лимитом 5 секунд экрана «Зачем открываешь?» с остатком лимита. Отсекает автоматические открытия.
5. **Статистика недели.** Сэкономленное время, сколько накоплено и потрачено, серия дней без превышения лимита.
6. **Экстренный пропуск.** Один раз в неделю можно открыть заблокированное приложение на 5 минут без банка (кроме вечной блокировки).

## 6. Порядок реализации (предложение)

1. Модель правил (раздел 1) и Room-таблицы.
2. Список покупок (простой, независимый, быстро даёт рабочую фичу).
3. Ежедневник + напоминания.
4. Банк времени (зависит от учёта использования и блокировки, которых пока нет).
5. Связки из раздела 5.
